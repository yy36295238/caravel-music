# 留声

简单的本地 MP3 播放器。Tauri 2 + 原生 JavaScript / CSS + Rust + SQLite，不捆绑 Chromium，不需要账号、服务器或联网服务。

支持喜欢 / 收藏、标签、批量分类、搜索、分页、播放队列、顺序 / 单曲循环 / 随机播放，专辑 / 歌手浏览、本地歌词，以及深色红、清新绿两款皮肤。原型保留在 `prototypes/`；正式应用入口为根目录 `index.html`。

## 使用

1. 打开应用，点击「导入音乐」或「音乐文件夹」，添加 MP3 所在目录，包含子目录。
2. 当前歌曲在曲库、底部播放器和播放队列显示小型律动条，暂停时静止，遵循系统减少动态效果设置。队列内可直接切歌或暂停，保持弹窗打开。点击歌曲名称播放；空格播放 / 暂停，Command / Ctrl + K 搜索。
3. 点击爱心收藏；在「设置 → 标签管理」创建标签，再通过歌曲右侧菜单或勾选批量整理。
   首页以导入目录的末级名称展示文件夹按钮，点击后显示该来源下所有歌曲（包含子目录），点击「全部」恢复曲库；搜索框也支持导入文件夹的末级名称，可与收藏、标签一起筛选。「播放全部」仅播放筛选结果，已建立的队列不随筛选改变。
4. 「音乐文件夹 → 刷新曲库」识别新增、删除和修改的文件。完整扫描后直接从曲库删除不存在的歌曲；扫描可取消，异常摘要在文件夹弹窗查看。目录卡片的「打开」调用 Finder / 资源管理器。
5. 左下角「设置 → 外观」即时切换皮肤；播放、队列和筛选保持不变。

目录、收藏、分类、音量、模式、队列、皮肤与进度自动保存。重新启动后不自动出声，点击播放继续。macOS 关闭窗口继续播放，Dock 图标重新打开，Command + Q 退出；Windows 关闭窗口退出，最小化继续播放。

不复制、不移动、不修改原始 MP3。移除目录仅停用来源并停止其中歌曲，收藏和分类保留；重新添加相同路径可恢复。文件移动到不同路径不自动迁移分类。完整扫描确认缺失的歌曲会从索引删除，同时清理其收藏、分类关联、播放队列与歌词偏移。目录离线、读取失败或取消扫描时保留记录，避免误删。

## 专辑、歌手与歌词

右栏仅保留当前歌曲与歌词，不常驻标签或校准说明。歌曲行和底部当前歌曲的「…」可查看 / 编辑标签；歌词「…」收纳来源、重新读取和单曲校准。

- 左侧「专辑」「歌手」按已有音乐索引整理，点击进入歌曲列表，可搜索、播放全部、收藏与批量分类。歌曲表格中的专辑、歌手名称也可以直接点击。
- 同名专辑按“歌手 + 专辑名”区分；合作歌手字段按原始整体名称处理。没有信息的歌曲归入「未知歌手 / 未知专辑」，不联网补全元数据。
- 点击播放器右侧「词」显示 / 隐藏应用内歌词，不再弹出独立面板；两款主题在宽窗口均放右侧，窄窗口统一放曲库上方，并隐藏装饰横幅以保留歌曲列表空间。关闭时收起整个右栏并让曲库占满可用宽度；切歌、换肤不会自动展开。
- 优先读取 MP3 同目录、同文件名的 `.lrc`（支持大写 `.LRC`）；没有有效外部文本时读取 MP3 的 ID3 USLT 内嵌歌词。示例：`晨间散步.mp3` 对应 `晨间散步.lrc`。
- LRC 支持分钟 / 秒 / 毫秒、多个时间标签、同时间译文、`offset`；当前行高亮并跟随播放，点击歌词可定位。无时间轴的内嵌歌词或纯文本按全文显示。
- 歌词播放期间逐帧读取音频进度，暂停或隐藏歌词后停止刷新。不同版本的音频与 LRC 若有固定偏差，可在歌词「…」中用「提前 0.2s / 延后 0.2s」校准（上限 ±30 秒）；点击中间时间复位。偏移按歌曲保存，重启保留，不修改 MP3 或 LRC；点击歌词跳转也使用校准后的时间。若偏差随播放不断变大，需要更换匹配音频版本的歌词。
- 滚轮浏览会暂停自动跟随，点击「跟随播放」可恢复。添加或修改 LRC 后在歌词「…」中点「重新读取」，无需重建曲库；Esc 或关闭按钮收起面板。
- 支持 UTF-8、带 BOM 的 UTF-16、常见 GBK 编码。单份歌词上限 1 MiB、10,000 行 / 时间点；不读越界链接，不改写 MP3 或 LRC。
- 不提供在线歌词搜索、逐字卡拉 OK 或 ID3 SYLT 二进制同步歌词解析。

运行 `node scripts/check-music.mjs` 检查专辑聚合、组合筛选与 LRC 解析；原有 `--self-check` 已补充歌词编码、读取优先级、体积与目录边界校验。

## 本地开发和打包

需要 Node.js 22+、Rust stable 与平台开发工具：macOS Xcode Command Line Tools；Windows Visual Studio C++ Build Tools、Windows SDK 和 WebView2。最低 macOS 12，Windows 10/11 x64；各平台应在本机验证系统解码和安装行为。

参考 caravel 的 `run.sh`，在 macOS 或 Windows Git Bash 中使用统一入口（也可以从其他目录通过绝对路径调用）：

```sh
./run.sh                     # 默认开发模式：原生窗口 + 前端热更新
./run.sh dev                 # 同上，Ctrl+C 停止
./run.sh build               # macOS 当前架构 .app；Windows NSIS 安装包
./run.sh build dmg           # macOS 当前架构 .app + DMG
./run.sh build universal     # macOS Apple Silicon + Intel 双架构 .app
./run.sh build universal dmg # macOS 双架构 .app + DMG，参数顺序不限
./run.sh build nsis          # Windows Git Bash，必须有 MSVC 工具链
./run.sh help
```

脚本检查 Node.js、Rust 和 macOS 构建工具；首次缺少 `node_modules` 时执行 `npm ci`。安装或更新依赖后可自行再次执行 `npm ci`。双架构构建会通过 `rustup` 安装两个 Rust 目标，首次需要联网。脚本沿用当前版本号，不自动升版。

开发端口为 1420；占用时先停止对应服务，再重新启动。脚本不会按端口终止其他进程。macOS 关窗仅隐藏播放器，结束开发请按终端 Ctrl+C。

产物位置：

- macOS 当前架构应用：`src-tauri/target/release/bundle/macos/留声.app`
- macOS 双架构应用：`src-tauri/target/universal-apple-darwin/release/bundle/macos/留声.app`
- DMG：`artifacts/留声_<版本>_macOS_<arm64|x86_64|universal>.dmg`
- Windows NSIS：`src-tauri/target/release/bundle/nsis/*-setup.exe`

macOS 使用系统 `hdiutil` 生成并校验 DMG，不依赖 Finder 排版脚本；失败时保留上一份有效 DMG。应用采用本机 ad-hoc 签名，不等同于开发者证书签名或公证。

原有 npm 命令仍可使用：`npm run app:dev`、`npm run check`、`npm run app:build:mac`（默认生成当前架构 DMG）。Windows PowerShell 可用 `npm ci`、`npm run app:dev` 和 `npm run app:build -- --bundles nsis`，不要求安装 Bash。

脚本参数与命令分发自查：`bash scripts/check-run.sh`，使用临时假命令，不安装依赖、不启动应用、不修改音乐库。

仓库包含 `.github/workflows/build.yml`，可在 GitHub Actions 手动构建 macOS Apple Silicon、Intel 与 Windows x64。工作流只上传构建产物，不创建发布或自动部署；在本地提供工作流不代表已经执行了云端构建。

当前开发包未配置开发者证书或 macOS 公证。Windows 安装器在缺少 WebView2 时联网安装运行时；已安装运行时后的音乐功能离线可用。

## 数据与实现

- macOS 数据：`~/Library/Application Support/com.liusheng.player/library.sqlite`
- Windows 数据：`%APPDATA%\com.liusheng.player\library.sqlite`
- 备份时先退出应用，再复制整个数据目录；恢复到相同原文件路径才能直接播放。
- SQLite 保存目录、歌曲、分类和设置；标签使用 `categories` / `track_categories` 两张表；旧分组数据仅保留兼容，应用不再提供分组功能。
- 扫描在后台执行，每 100 首提交一批。添加目录时跳过未变化文件的标签解析；手动刷新曲库会重读标签，修正已有索引。完整扫描后才清理缺失歌曲，并在结果中显示清理数量。
- 完整歌名 / 歌手标签优先；缺少歌名时，带序号的 `001.歌名 - 歌手.mp3` 按文件名识别，若已有歌手与左侧一致则按 `歌手 - 歌名` 识别。无序号且无标签时仍按 `歌手 - 歌名` 兜底。不写入或修改原始 MP3。
- 不到 1 万首的索引元数据在界面内搜索，每页渲染 100 行；音频不进入这份索引。搜索支持中文、大小写不敏感和多个标签交集。
- 单个音频元素通过受限 `music` 协议按 ID 读取文件。每次校验真实路径与目录权限，Range 请求最多读取 1 MiB；不使用 Base64。
- 非 Range 媒体请求会回退整文件响应，超大音频不是首版优化目标；不读取 ID3 封面。对异常音频显示错误并允许继续使用曲库。
- 后端日志由系统应用日志目录保存，单个日志上限 2 MB，仅保留一个轮转文件。

增加皮肤：在 `src/main.js` 的 `skins` 增加注册项，在 `src/themes.css` 增加对应 `[data-theme="皮肤ID"]` 样式；不复制业务代码。发布前验证窄窗口、键盘焦点、文字对比度及播放中换肤。

## 可运行自查

构建后运行，使用临时目录，不接触应用数据库或个人音乐库：

```sh
src-tauri/target/release/liusheng --self-check
# 可选：提供自己的测试 MP3，额外检查真实标签和时长解析。
LIUSHENG_CHECK_MP3=/path/to/sample.mp3 src-tauri/target/release/liusheng --self-check
```

Windows 对应执行 `src-tauri\target\release\liusheng.exe --self-check`；PowerShell 可先设置 `$env:LIUSHENG_CHECK_MP3`。检查覆盖扫描、重复目录、损坏标签、收藏分类持久化、删除分类级联、移除 / 恢复目录、文件缺失、Range 请求和路径边界。系统 WebView 实际播放、定位和安装仍需在目标平台手动验收。

### 菜单栏播放器与设置

macOS 顶部菜单栏显示留声的四柱图标：悬浮展开小播放器，移开约 450 毫秒后收起；点击图标固定展开，再次点击、Esc、关闭按钮或切换窗口可收起。浮层支持上一首、播放 / 暂停、下一首和打开主窗口，队列边界与离线歌曲自动禁用对应按钮。关闭主窗口后仍能控制同一个播放器。

图标随播放状态轻微律动，暂停时停止；这是状态动画，不是音频频谱分析。系统启用「减少动态效果」时停用动画。浮层与主窗口共用深色红 / 清新绿皮肤变量，新增皮肤只需维护同一份主题。

标签管理和皮肤选择已收进左下角「设置」，窄窗口也有设置入口；标签筛选和歌曲标签编辑保持可用。设置改动即时保存。应用激活时可用 `⌘⇧M` 或应用菜单中的「菜单栏播放器」打开同一浮层，支持键盘 Tab / Space 操作。

### 菜单栏定位与歌词跟随修正

菜单栏小播放器卡片改为 248 × 136pt、16pt 圆角，透明窗口仅留四周阴影；macOS 使用 AppKit 点坐标选屏并定位，图标矩形按所在屏幕缩放还原。鼠标只触发展开，浮层固定在图标中心下方；同屏已展开时不重复定位。边缘图标会约束在当前屏幕可用范围内。

主界面默认展示歌词：两款主题在宽窗口均放右侧，窄窗口统一放曲库上方，并隐藏装饰横幅以保留歌曲列表空间。「词」控制同一歌词区域的显示 / 隐藏，不再重复展示浮层。正常播放使用平滑滚动；打开面板、拖动进度和减少动态效果时立即定位。歌词高亮不改变字重和行高，避免换行与滚动锚点导致抖动。手动浏览暂停歌词跟随，切歌后恢复跟随但不改变显隐状态。

原生 `--self-check` 补充主屏 / 扩展屏隔离、负坐标、上下排列、边缘约束及鼠标移动时图标锚点不变的断言；前端自查补充歌词居中与首尾边界。

### 浮层停留与播放模式

鼠标停留在菜单栏浮层（含边缘）或图标到浮层的过渡区域时保持显示；连续离开约 450 毫秒才收起。自动收起直接检查 macOS 鼠标与窗口位置，不依赖未激活网页的鼠标进入 / 离开事件；短暂失焦不会打断按钮操作。关闭按钮、Esc 和再次点击固定图标仍可主动收起。

浮层左下新增播放模式按钮，依次切换「顺序播放 → 单曲循环 → 随机播放」，与主播放器的队列和已保存模式同步，不改变当前歌曲的播放进度。本轮由开发侧执行编译和基础自查，鼠标与按钮交互由用户验收；未重新生成安装包。
