# 歌词来源与本地复用

核对日期：2026-09-28。留声当前读取本地 LRC 和 ID3 USLT 内嵌歌词。应用内尚未接入在线歌词服务，仓库提供独立 LRCLIB 命令行脚本。

## 查询与下载脚本

脚本：[`scripts/lyrics_lrclib.py`](../scripts/lyrics_lrclib.py)。需要 Python 3.10+，在项目根目录执行：

```bash
python3 -m venv artifacts/lyrics-tools
artifacts/lyrics-tools/bin/python -m pip install -r scripts/lyrics-requirements.txt

# 预览前 10 首缺词歌曲的匹配结果，不写入歌词。
artifacts/lyrics-tools/bin/python scripts/lyrics_lrclib.py \
  "/Users/yangyu/Music/Music" --limit 10

# 查询所有缺词歌曲，将符合条件的歌词保存到 MP3 旁边。
artifacts/lyrics-tools/bin/python scripts/lyrics_lrclib.py \
  "/Users/yangyu/Music/Music" --download

# 只重试旧报告中的未匹配、待确认、失败、信息不足及未查询记录。
artifacts/lyrics-tools/bin/python scripts/lyrics_lrclib.py \
  "/Users/yangyu/Music/Music" --download \
  --retry-report "/Users/yangyu/Music/Music/lrclib-report-20260928-211826-052231.csv"
```

路径可替换为任意音乐目录。Windows 使用 `python -m venv artifacts/lyrics-tools` 创建环境，并将命令中的 Python 路径替换为 `artifacts/lyrics-tools/Scripts/python.exe`。

脚本递归扫描 MP3，优先使用标签中的歌名、歌手、专辑、时长。对于 `007.歌名 - 歌手.mp3` 编号歌单，歌名标签缺失、等于完整文件名，或歌手是“华语群星”等通用标记时，根据明确的文件名信息回退。已有歌手与左侧一致时仍按“歌手 - 歌名”处理；缺少歌手时，可用现有歌名或上级目录名判断方向，支持 `岁月无声（粤语）- BEYOND.mp3` 这样的单侧空格格式。不拆开 `BYE-BYE` 等英文连字符歌名，不修改 MP3 标签。报告的“信息来源”列说明识别依据。

已有同名 LRC（包括 `.LRC`、空文件）一律保留，已有 USLT 内嵌歌词则跳过。遇到非标准 TEXT、TXXX 或 SYLT 歌词会报告“需提取本地内嵌歌词”，避免重复在线查找；脚本本身不负责提取这些标签。

匹配时统一繁简体、大小写和标点，合作歌手允许分隔符和排列顺序不同，不猜测歌手别名。只去掉明确的电影、电视剧主题曲等宣传附注，未知括号内容保留。原始查询未得到确定匹配时，再尝试基础歌名和繁体查询，单首最多三种查询组合；候选始终与原曲的语言、Live、Remix、伴奏等版本标记比较。语言只在一侧出现时列为待确认，不猜测国语或粤语。

时长差不超过 3 秒的候选可进入自动匹配；3～8 秒仅在专辑一致且同步歌词时间轴有效时进入自动候选，否则待确认；超过 8 秒排除。同专辑优先，其次同步歌词，最后按时长接近程度排序。同级候选比较时忽略署名、标点、繁简体差异；正文不同仍待确认。正文一致但时间轴不同，仅允许逐行误差不超过 0.6 秒，或同专辑的最佳候选时长差不超过 0.5 秒且比次选至少接近 1 秒，否则待确认。下载内容保持来源原文。

同步歌词会校验大小、时间戳及 offset 后的有效时间；超过本地时长 3 秒或存在无效秒数时不采用该时间轴。没有可用同步歌词时可保存普通文本，报告明确区分“已下载同步歌词”和“已下载纯文本歌词”，后者不支持滚动。“匹配可信度”是元数据与候选一致性的判断，不代表已试听确认每个时间点。

每次运行在音乐根目录创建 `lrclib-report-时间.csv`，表头和处理结果均为中文，包含候选歌名、歌手、专辑、时长差、可信度、来源链接和处理原因。未匹配时会细分接口无结果、歌名不符、歌手不符、录音版本不符、时长不符或歌词不可用；“参考候选”展示最多三条按时长接近排序的结果，参考结果不等于已匹配。

可通过 `--report /路径/报告.csv` 指定位置，报告不覆盖同名文件。`--limit N` 限制本次处理的缺词歌曲数（0 为全部），不限制本地扫描；每首可能有多个回退请求。`--retry-report` 兼容旧版英文报告与新版中文报告，仅选中未完成记录；仍先检查现有歌词，避免重复下载。报告中的相对路径必须位于指定音乐根目录内，已成功或纯音乐记录不重试。

### 终端进度

脚本先完成本地扫描，显示 MP3 总数、已有 LRC / 内嵌歌词、待本地提取、缺元数据、读取失败以及可在线查询的待补数，再开始联网。待补数不代表一定能下载成功；`--limit` 会进一步限定本次计划查询数。

每首开始时显示 `正在处理 [当前序号/计划查询数]`，结束时更新累计进度。以下为 5 首待补歌曲的示例：

```text
待补歌词 5 | 本次计划查询 5 | 超出查询上限 0（匹配成功才下载）
查询进度 [5/5 100.0%] | 已下载 2（同步 1 / 纯文本 1） | 未匹配 1 | 待确认 1 | 失败 0 | 纯音乐 1 | 剩余待查询 0
```

百分比表示本次查询处理进度，不是歌词补全率。已下载只统计本轮实际保存成功的文件；预览显示“预览匹配”和“已下载 0”。HTTP 重试不重复计入进度，重试耗尽或保存失败才计作失败，未匹配与待确认单独统计。扫描读取错误单列，不混入查询失败数。正常结束、限流停止、查询阶段按 Ctrl+C 中断时均显示汇总；未查询的数量不会假装已完成。重跑会重新扫描，先前下载的文件归入已有歌词。

请求保持证书验证，每秒最多发起一次；相同歌名与歌手复用本次查询结果。网络错误最多尝试三次，默认间隔 5 秒、15 秒；429 / 503 优先遵守 `Retry-After`。服务要求等待超过 60 秒、三次仍被限流，或连续三次查询均耗尽网络重试时，暂停整批并保留剩余记录。其他单曲失败记录为“查询或处理失败”后继续；出现处理错误或服务暂停时退出码为 1，用户中断为 130。重跑会跳过已经保存的歌词，不覆盖或修改 MP3。脚本沿用系统代理；若连接失败，请检查代理是否仍在运行。

使用时遵循来源服务及歌词内容的适用授权。预览也会查询服务，但不会将歌词正文保存为文件。

验证记录：临时 MP3 与自写歌词覆盖了同步/纯文本保存、预览不写入、重复执行不覆盖、USLT/TXXX 检测、繁简体及影视附注、合作歌手顺序、语言/Live 保护、时间轴校验、中文/旧英文报告重试、报告路径边界、限流及持续网络失败暂停。进度统计覆盖查询上限、零待补、读取失败和用户中断。

## 后续匹配规则

1. 先检查同目录 LRC 和用户已有的内嵌歌词，避免重复查找及覆盖。
2. 以歌名、歌手查询，再核对专辑、时长及版本。保留 Live、国语、粤语、伴奏、翻唱等版本信息，不能为了命中直接删除。
3. 时长差不超过 3 秒只作为候选筛选条件；同名异曲、多版本、合作歌手和标题附注仍需确认。查询无结果不等于词库永久缺失。
4. 区分同步歌词、普通歌词和纯音乐。普通歌词没有时间轴，不能承诺自动跟随；纯音乐不应计作歌词缺失。
5. 外部查询设置超时、限制并发；收到限流响应时遵守服务提示，保留失败记录，避免反复请求。

## 已有或获授权歌词的本地使用

- 将歌词存成与 MP3 同目录、同名的 UTF-8 `.lrc`，例如 `歌曲.mp3` 对应 `歌曲.lrc`；不改写 MP3，不覆盖已有有效歌词。
- 使用 `src/lyrics.js` 的 `parseLyrics` 验证格式，确认时间点合理。播放器支持的大小上限为 1 MiB、10,000 行 / 时间点。
- 在播放器歌词「更多 → 重新读取」中加载。固定时间偏差可使用单曲校准；偏差持续增大通常需要更换相符的录音版本。
- 保存来源链接、版本信息和适用授权，便于以后复核。歌词正文及个人曲库清单不纳入代码仓库。
