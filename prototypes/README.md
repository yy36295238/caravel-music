# 留声 · 多皮肤静态交互原型

双击 [index.html](index.html) 即可打开统一入口，无需安装依赖、编译或启动后端。请保留同目录的 `app.js`、`styles.css` 和 `assets` 文件夹。

- [A 版：深色红](netease.html)：参考网易云音乐的深色侧栏、红色强调、固定播放栏，带右侧歌曲详情。
- [B 版：清新绿](qq.html)：参考 QQ 音乐的浅色侧栏、绿色强调、开放式介绍区与宽列表。

两款皮肤均为独立设计，使用“留声”名称；没有使用网易云或 QQ 的品牌标识、官方素材或服务。

页面中的“更换皮肤”可即时切换这两种外观并记住选择。原有 `netease.html` / `qq.html` 入口继续可用：没有保存偏好时分别默认深色红和清新绿，有偏好时优先恢复偏好。

## 可以操作的功能

- 即时更换皮肤，不刷新页面，不中断播放，不丢失搜索、勾选、队列或本次导入文件。
- 搜索歌曲、歌手和文件名；收藏、分组、多个标签可叠加筛选。
- 点击歌曲名或封面播放，支持暂停、上下首、进度、音量、静音、顺序/单曲循环/随机播放与队列查看。
- 点击爱心收藏或取消收藏，在“我喜欢的”中查看。
- 创建、重命名、删除分组和标签；行尾“…”编辑单曲分类，勾选歌曲后批量添加或移除分类。
- 导入多个 MP3 或整个文件夹，通过浏览器在本地播放，不上传、不修改文件。
- 收藏、分组、标签、曲库元数据和播放状态保存到浏览器 localStorage，重开后默认暂停。
- 支持小屏布局；`Command/Ctrl + K` 定位搜索，非输入控件聚焦时空格控制播放。

## 静态原型的边界

- 曲库中 10 个示例条目复用 3 段本地合成的 18 秒试听；不是商业歌曲录音，所有试听资源均随目录提供。
- MP3 导入后，歌名和歌手暂从“歌手 - 歌名.mp3”文件名推断，不解析 ID3；时长在首次加载播放后取得。
- 浏览器不会永久保留对本地音频的访问权。刷新、打开其他 HTML 入口或重新打开后，需要重新选择同一文件；已有收藏和分类继续保留。页面内“更换皮肤”不受此限制。
- 原型通过相对路径/文件名、大小、修改时间识别重选文件。改名、移动或换用不同导入方式可能视作新文件；没有桌面版的路径授权和自动扫描能力。
- localStorage 有容量限制；直接用 `file://` 打开时，其可用性及两版数据是否共享取决于浏览器。正式桌面版仍应采用设计方案中的 SQLite。
- 当前没有目录移除管理、自动刷新、真实大曲库性能验证或桌面系统集成。

## 后续增加皮肤

1. 在 `app.js` 的 `skins` 中增加唯一 ID、名称、色彩方案、配色、标题和说明。
2. 在 `styles.css` 中添加对应的 `body[data-theme="皮肤ID"]` 样式，复用现有 CSS 变量和组件。
3. 检查换肤不中断播放、保存后可恢复、两端布局和文字对比度；不需要增加 HTML 页面或修改音乐业务。

所有皮肤内置、离线加载；当前不做在线皮肤下载或主题编辑器。

## 验证

运行无依赖的规则检查：

```sh
node prototypes/check.cjs
```

已在 Chrome 中验证：中文搜索、收藏切换、分组创建/重命名/删除、单曲及批量分类、分类刷新保留、组合筛选、内置音频播放/暂停和进度调整、播放模式切换；新增验证了播放中即时换肤、搜索和勾选保持不变、刷新后恢复皮肤，以及小屏换肤入口；检查了桌面、1280 × 800 和 390 × 844 布局。

MP3 文件选择对话框能够打开，但自动填入测试文件被 Chrome 扩展的本地文件权限阻止，因此“选择 MP3 → 播放”仍需手动验证；没有将其记为已通过。Windows 和 Safari 尚未实机验证。

`previews/` 保存两版界面预览图。预览图只是效果参考，HTML 本身可以交互。
